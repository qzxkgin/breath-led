# 呼吸灯联调：电控侧交接材料

视觉端会连续发送 RGB 颜色值，你收到后把颜色显示在灯上，灯的变化就是呼吸效果。

## 一、你要做的事

每 20 ms 收一帧 6 字节数据，解出 R、G、B，写到灯上。**不需要回包**，也不需要自己做渐变——呼吸是视觉端在时间上算出来的。

## 二、接线

- 视觉端 TX → 你的 RX，你的 TX → 视觉端 RX（本协议不回包，但接上方便以后扩展）
- **GND 必须共地**
- 3.3 V TTL 电平，**115200 8N1**，无流控

## 三、协议速查（完整版见 protocol.md）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xA5` |
| 1 | R | 0~255 |
| 2 | G | 0~255 |
| 3 | B | 0~255 |
| 4~5 | CRC16 | 算前 4 字节，低字节在前 |

CRC 参数：CRC-16/CCITT-FALSE，poly `0x1021`，init `0xFFFF`，不反转，xorout 0。
先跑这个验证向量：对 `"123456789"` 算出 **`0x29B1`**，对上再继续。

固定 6 字节、只有一个方向，收满就处理，没有长度字段。

## 四、解包代码

`breath_ecu.c` 可以直接接进 CubeMX 工程：

- `breath_ecu_init()` 启动 PWM 和三路输出，再开单字节中断接收
- `HAL_UART_RxCpltCallback` 里把字节喂给 `breath_ecu_on_byte()`
- 状态机：等帧头 → 收满 6 字节 → 校验 CRC → 写 PWM；**校验失败只丢 1 个字节**，不要整包丢

接入时注意：如果你工程里已经有 `HAL_UART_RxCpltCallback`，把内容合并进去，不要重复定义。

如果灯是 WS2812 而不是三路 PWM，把 `led_apply()` 换成写灯珠函数，注意数据顺序是 **GRB**。

## 五、没有视觉主机时怎么自测

**方法 A：串口助手定时发送（推荐，零依赖）**

1. 串口 115200、8 位、无校验、1 停止位
2. 发送区切 HEX 模式，填 `a5 ff 00 00 90 1d`（纯红）
3. 勾选「定时发送」，周期 20 ms
4. 灯应该是纯红，一直亮着

**方法 B：replay.py（需要 Python + pyserial）**

```
python replay.py COM3
python replay.py COM3 --color 0,160,255 --freq 0.5 --seconds 10
```

它按 50 Hz 发同样的包，会看到 2 秒一个来回的呼吸，相当于提前验证整条链路。

**方法 C：离线喂数据（连串口都不用）**

`sample_frames.txt` 是 100 帧真实数据（2 秒、50 Hz、青色呼吸），一行一帧。把解包函数按顺序喂这 100 行，应该 **100 帧全过、0 帧丢弃**。建议在接硬件之前先把这一步跑通。

## 六、验收标准

| 发这 6 个字节 | 灯应该是 |
|---|---|
| `a5 ff 00 00 90 1d` | 纯红 |
| `a5 00 ff 00 0c d1` | 纯绿 |
| `a5 00 00 ff 03 cc` | 纯蓝 |
| `a5 ff ff ff 9f 00` | 白 |
| `a5 00 00 00 f3 d2` | 灭 |
| replay.py 跑 10 秒 | 明暗呼吸，2 秒一个来回 |

更多样例见 `test_vectors.md`。

## 七、联调要准备的东西

- USB 转 TTL 模块（CH340 / CP2102）或板载 UART 排针
- 杜邦线至少 3 根（TX、RX、GND）
- 灯和驱动（三路 PWM 或 WS2812）
- 能烧录的工程，最好提前把 PWM 和串口收包调通

## 八、需要回给视觉端的信息

1. 收**二进制 6 字节帧**，还是收 **ASCII 文本**（比如 `255,128,0\n`）？两种实现不兼容，必须先定
2. 用哪个 USART、引脚号多少，这个串口有没有被 printf 调试输出占用
3. 115200 波特率能不能用，你那边现有配置是多少
4. 灯是三路 PWM 还是 WS2812（WS2812 的话数据顺序是 GRB）
5. 你们工程里有没有已经定好的包格式——**有的话以你们的为准**，视觉端改字段即可
6. 联调时间和地点，谁带线
