# 测试向量

## 1. CRC 自检（先做这一步）

CRC-16/CCITT-FALSE，poly `0x1021`，init `0xFFFF`，refin/refout 都关闭，xorout `0x0000`。

对 ASCII 字符串 `"123456789"`（9 个字节，`31 32 33 34 35 36 37 38 39`）计算结果必须是：

```
0x29B1
```

两种写法的结果都要是这个数：

- 算完直接 `return crc`（本协议就是这种）
- 先算前 4 字节再比较

对不上就说明 poly、init、反转、字节序里有一个不一致，后面所有包都会被丢掉。

## 2. 固定颜色帧

可以直接抄进串口助手（HEX 发送），或者写进单元测试。

| 颜色 | RGB | 完整帧（6 字节） |
|---|---|---|
| 黑 / 关灯 | 0,0,0 | `A5 00 00 00 F3 D2` |
| 红 | 255,0,0 | `A5 FF 00 00 90 1D` |
| 绿 | 0,255,0 | `A5 00 FF 00 0C D1` |
| 蓝 | 0,0,255 | `A5 00 00 FF 03 CC` |
| 白 | 255,255,255 | `A5 FF FF FF 9F 00` |
| 橙 | 255,128,0 | `A5 FF 80 00 08 06` |
| 青蓝（默认色峰值） | 0,160,255 | `A5 00 A0 FF 7D D1` |
| 暗橙（约 50%） | 128,64,32 | `A5 80 40 20 07 C0` |

每行末尾两个字节是 CRC，低字节在前。例如 `A5 FF 00 00` 的 CRC 是 `0x1D90`，所以写成 `90 1D`。

## 3. 呼吸过程中的帧（50 Hz，0.5 Hz 呼吸，基准色 0,160,255）

| 时间 | RGB | 完整帧 |
|---|---|---|
| 0.00 s | 0,0,0 | `A5 00 00 00 F3 D2` |
| 0.04 s | 0,1,1 | `A5 00 01 01 E3 F1` |
| 0.08 s | 0,3,4 | `A5 00 03 04 24 C7` |
| 0.98 s（峰值） | 0,160,255 | `A5 00 A0 FF 7D D1` |
| 1.98 s | 0,0,0 | `A5 00 00 00 F3 D2` |

完整的 100 帧在 `sample_frames.txt`（2 秒、50 Hz）。按顺序喂给解包函数，应该 100 帧全过、0 帧丢弃。

## 4. 用串口助手手动测

1. 打开串口：115200、8 数据位、无校验、1 停止位、无流控
2. 发送区切 **HEX**
3. 填一帧，比如 `A5 FF 00 00 90 1D`
4. 点发送，灯应该变成纯红并保持
5. 打开「定时发送」，周期填 20 ms，灯保持红色不闪
6. 把帧换成 `A5 00 FF 00 0C D1`，灯变绿；换成 `A5 00 00 00 F3 D2`，灯灭

## 5. 现象与原因

| 现象 | 原因 |
|---|---|
| 完全没反应 | 波特率不对、TX/RX 没交叉、没共地、CRC 一直不通过 |
| 偶尔闪一下 | 校验通过率低：先确认 CRC 自检向量 |
| 颜色红绿颠倒 | RGB 顺序或 WS2812 的 GRB |
| 亮度不对（该亮的地方不亮） | PWM 比较值范围不是 0~1000，或者 ARR 设置不匹配 |
| 灯常亮不变化 | 解包失败后没更新，卡在第一帧；加个「超时灭灯」更容易看出问题 |

## 6. 建议加的超时保护

超过 200 ms 没收到合法帧就灭灯。这样视觉端崩了、线掉了，灯不会一直亮着误导人。
